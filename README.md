# АЛКО НОЧЬ — сайт для домена 24alkomoscow.site

Статический сайт (HTML + CSS + JS без сборщиков и сервера), перенесённый из папки `site1`
(«АЛКО НОЧЬ») репозитория `tengizkaa-coder/oskar` и пересобранный с нуля: дизайн, цвета,
логотип и название сохранены, все зависимости (`site-previews/`, `img/`) перенесены внутрь
репозитория, структура каталога и тестового просмотра переделана.

## Структура

| Раздел | Адреса |
| --- | --- |
| Главная | `/` |
| Каталог (все 30 позиций, поиск, корзина) | `/catalog/` |
| 10 разделов каталога | `/catalog/whisky/`, `/vodka/`, `/gin/`, `/cognac/`, `/liqueur/`, `/vermouth/`, `/white-wine/`, `/red-wine/`, `/sparkling/`, `/beer/` внутри `/catalog/` |
| 30 страниц товаров | `/catalog/product/<товар>/` |
| Доставка + 12 округов Москвы | `/delivery/`, `/delivery/<округ>/` |
| Вопросы и ответы | `/faq/` |
| Тестовый просмотр (весь сайт целиком) | `/test/`, `/test/catalog/`, `/test/delivery/`, … |
| Служебное | `404.html`, `test.html` (переход в `/test/`) |

Всего **56 рабочих страниц** и столько же в `/test/`. Все ссылки относительные, поэтому сайт
работает и в корне домена, и в подпапке вида `…github.io/OSCAR-1/`.

## Каталог и подразделы: как всё связано

```
/                       главная: 30 карточек, 11 фильтров, поиск, 10 категорий
└── /catalog/           все 30 позиций по разделам + поиск + корзина
    ├── /catalog/whisky/            5 позиций, сетка всех категорий, «Другие разделы»
    │   └── /catalog/product/jameson/   цена по телефону, «Ещё в разделе «Виски»», хлебные крошки
    ├── /catalog/vodka/             4 позиции
    └── … ещё 8 разделов
/delivery/              12 округов Москвы
└── /delivery/cao/      условия по округу + ссылки на остальные 12
/faq/                   6 вопросов
```

Каталог, карточки, фильтры, номера позиций и три бутылки в «герое» **отрисованы статически в
HTML** — каталог виден даже если JavaScript не загрузился или отключён. Скрипт `app.js` только
скрывает лишние карточки при выборе фильтра или вводе поиска и перенумеровывает видимые.

## Как устроена сборка

`tools/build.py` собирает оба дерева страниц из одного описания. Ссылки не переписываются
регулярками, а строятся по контексту страницы:

```python
Ctx.page('catalog/whisky/')   # ссылка на страницу того же дерева
Ctx.asset('img/jameson.png')  # ссылка на общий файл: img/, assets/, logo.svg
```

Отсюда гарантия: из рабочего дерева нельзя попасть в `/test/`, а из `/test/` — в рабочее
дерево. Тестовые страницы ссылаются только на себя и на общие картинки/стили; единственные
осознанные ссылки наружу — «рабочий сайт» в жёлтой полосе теста (помечены
`data-tree="production"`).

```
python3 tools/build.py                    # домен из tools/site_config.py
python3 tools/build.py --domain https://new-domain.ru
python3 tools/check.py                    # обход ссылок, SEO, schema.org, sitemap
```

Правки контента: `tools/site_config.py` (телефон, Telegram, бренд, категории, округа, FAQ,
аналитика) и `tools/data/products.json` (`[категория, название, объём, фото]`).

## Ограничения доступа

`assets/js/gate.js` (логика скопирована с основного сайта «АЛКО МСК»):

| Посетитель | Результат |
| --- | --- |
| Поисковый робот (Googlebot, YandexBot, Bingbot и др. по user-agent) | доступ открыт |
| Телефон + переход из Google / Яндекса / Bing / DuckDuckGo / Mail.ru | доступ открыт, вход запоминается в `sessionStorage` на вкладку |
| Телефон + внутренние переходы после такого входа | доступ открыт |
| Телефон + прямой вход | белый экран с текстом «Ошибка загрузки страницы.» |
| Компьютер (любой вход) | **белый экран без текста** |
| `/test/` и весь тестовый сайт | открыт всем, `noindex,nofollow` |

Это клиентская проверка, **не защита файлов**: `User-Agent` и `Referer` подделываются, файлы
доступны по прямой ссылке. Она же мешает SEO и переходам с внешних ссылок:

- iPhone Safari с «Предотвращать перекрёстное отслеживание» может не передать `Referer` от
  Google → посетитель увидит «Ошибку загрузки страницы»;
- внутренняя ссылка, открытая в новой вкладке, сбрасывает `sessionStorage` → снова белый экран;
- переходы из мессенджеров, закладок и рекламы с телефона закрыты, компьютеры закрыты всегда.

Снять ограничения (только по решению владельца): убрать подключение `gate.css`/`gate.js`
в функции `render()` в `tools/build.py` и пересобрать сайт.

## Корзина, цены, объёмы

- Корзина — список в `localStorage` (`selection-alkonoch-v1`), переживает переходы между
  страницами, **никуда не отправляется**; оформление открывает звонок. У `/test/` отдельная
  корзина (`selection-alkonoch-test-v1`), чтобы тест не смешивался с рабочим сайтом.
- Цен нет нигде, в `Offer` нет `price` (проверяется автоматически).
- Объёмы взяты из исходного каталога и по фото не проверялись — на странице товара об этом
  написано.
- Телефон +7 (495) 095-95-99 (`tel:+74950959599`), Telegram @alkomsk_shop_bot — на всех страницах.

## SEO и домен

- `title`, `description`, `H1`, `canonical`, Open Graph — на каждой рабочей странице;
  `sitemap.xml` (56 адресов), `robots.txt`, `CNAME` под `24alkomoscow.site`.
- JSON-LD: `WebSite`, `Store` (телефон, Telegram, зона «Москва», 24/7, каталог категорий),
  `CollectionPage` + `ItemList` на каталоге и разделах, `Product` + `Offer` (без цены) и
  `BreadcrumbList` на товарах, `FAQPage` на вопросах.
- Адрес физической точки не указан: для нового бренда он не подтверждён и на страницах его нет.
  Появится — впишите в `STORE_ADDRESS` в `tools/site_config.py`.
- Тестовые страницы: `noindex,nofollow`, без canonical, закрыты в `robots.txt`.

## Аналитика (необязательно)

Пока `YANDEX_METRIKA_ID` и `GA4_ID` в `tools/site_config.py` пустые, сторонних скриптов на
сайте нет. Впишите номер счётчика Метрики или `G-…` из GA4 → `python3 tools/build.py` → push.
Счётчики не ставятся на `/test/`, `404.html`, `test.html` и не срабатывают у посетителей,
которым доступ закрыт.

Что смотреть: **Google Search Console** (`search.google.com/search-console`) и
**Яндекс.Вебмастер** (`webmaster.yandex.ru`) — показы, клики, индексация (это не зависит от
счётчиков); Метрика/GA — посещаемость. Статистика будет неполной: заблокированные посетители
в неё не попадают. GitHub Pages своей статистики посещений не ведёт.

## Публикация: пошагово

1. Влить ветку в `main` (PR или `git checkout main && git merge --ff-only arena/990c5ed0-oscar-1 && git push`).
2. Settings → Pages → Source: *Deploy from a branch*, ветка `main`, папка `/ (root)` → Save.
3. Settings → Pages → Custom domain: `24alkomoscow.site` → Save → включить **Enforce HTTPS**.

   > Домен вы указали как `http://24alkomoscow.site/`; canonical, sitemap и `CNAME` собраны под
   > `https://24alkomoscow.site`. Если HTTPS включить не удастся — скажите, пересоберу под http.

4. DNS у регистратора:

   | Тип | Имя | Значение |
   | --- | --- | --- |
   | A | `@` | `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` |
   | AAAA | `@` | `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153` |
   | CNAME | `www` | `tengizkaa-coder.github.io` |

5. После публикации проверить фактом, а не на словах:

   ```bash
   curl -I https://24alkomoscow.site/            # 200 и HTTPS
   curl -s https://24alkomoscow.site/robots.txt
   curl -s https://24alkomoscow.site/sitemap.xml | head
   ```

6. Добавить домен в Search Console и Вебмастер, отправить `sitemap.xml`. Сайт **не опубликован**
   и не индексируется, пока вы это не сделаете.
